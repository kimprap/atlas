## Scope and effects

- Scope: T1 builds the host-neutral core. `atlas/core/reply.py` keeps the stage 1 strict body decode and six-key reply and adds the `decisions[]` item shape of spec 4.1 (`id`, `kind` from the spec's eight kinds, `question`, `options[]` with `id`, `label` and a typed `then` of `resend`, `skill` or `stop`), the decision id (first 16 hex of SHA-256 over the command, the mode flag, the canonical body without `approval`, and `kind`), and the check that turns an `approval.decision` that differs from the id of the change being resent into exit 2 "this approval is for a different change"; exit 4 is the reply whose `decisions` is non-empty. A new `atlas/core/config.py` reads `config.toml` with `tomllib` (stage 2 keys only: `default_profile`, and per profile `store` with `~` expanded, and `judge` ∈ `jev` | `opus`), resolves the profile, and reports exit 3 with `result.needs_action` for no config, an unknown or missing profile, or a profile without `store`. A new `atlas/store/` package holds the store interface and its SQLite adapter: one file per profile, created on first open with its parent folder, WAL mode and foreign keys on, the schema rebuilt from `atlas/store/schema_dev.sql` (no tables in stage 2) when its text changes, and exit 1 "store is newer than this Atlas; check out a newer tag" when the file's `user_version` is newer than the code's; every resolved command opens its profile's store. A new `atlas/ports.py` holds the read, call, judge and quota ports and the host facts capability with the value types and errors of spec 4.3 (frozen dataclasses and Protocols), and a `Host` value carrying `read`, `call`, `judge` or none, `quota` or none, `facts` or none, and the store opener. A new `atlas/core/status.py` answers `status` as spec 4.13 says, limited to the items whose inputs exist in stage 2, in this order: no config or profile (fix: run `atlas-init`; on `status` this item comes first and, as spec 4.4 and 4.16 say, is followed by the missing-role items with `role_fix` lines from host facts, so `atlas-init` takes the lines from `status` on a fresh machine; no store or judge is used before setup resolves, and every other command keeps the one not-set-up item — the human's decision of 2026-11-09, "Follow the spec: status lists role items", replacing this plan's earlier "ends the reply alone"), store newer than code, missing `atlas_*` roles (fix lines from `facts.role_fix`, else role names and suggested models without host syntax), the judge's `setup_problem()` when the profile's judge is `jev`, judge choice not saved, and the host version warning (`facts.version()` against the host-version trailer of the nearest `v2` tag in a checkout, never blocking; the trailer key `Omp-Version` is a constant in `atlas/ports.py`, because spelled under `atlas/core/` it would match AC-X1's case-insensitive whole-word `omp`); one summary line naming the profile, the judge and the Atlas version (`git describe --tags --match 'v2.*'` in a checkout, else the `package.json` version); `detail` only on `--detail` (profile, store path and size, roles and models, judge, Atlas and host versions); `next` holds 1–3 items, so a ready reply still ends with Next. Price rows, cap, windows, spend, counts and confirm settings arrive in stage 3 with their first consumer. `atlas/core/app.py` routes `status` through config, store and status and keeps every other command's stage 1 replies after setup resolves. `tests/fakes/fake_host.py` implements every port and the facts capability from in-memory scripts (pages by link, replies by role and turn, judgments by question, windows, roles, version, setup problem) and records each call, written to the contract cases of spec 4.3 so T2's suite binds it unchanged. Tests: `tests/test_reply.py` (AC-2.1: reply keys and exit codes through `cli.py` as a subprocess only for replies that end before a `Host` is used, which are bad input (exit 2) and not set up (exit 3), because `cli.py` passes no `Host` until T2 wires it and must then start no host process in a test; exit 0, 1 and 4, the decision shape and the id binding through `app.run` with the fake host and on `reply.py` directly), `tests/test_status.py` (AC-2.4, through `app.run` with the fake host and a temporary `HOME`), and store cases on a temporary file (rebuild on schema change, newer-store stop) in the file the child judges their primary owner under test-value; `tests/test_cli.py`'s case that an empty `config.toml` ends the not-set-up reply is now wrong (an empty file has no profile, so exit 3) and is changed or merged into `tests/test_reply.py`. T2 builds the adapters and their proof. `atlas/adapters/omp.py` implements read (`omp read <link>`, 90 s timeout; header lines parsed and removed, `URL:` → `final_link`, `Method` → `kind_hint`, GitHub and X counter lines removed;
